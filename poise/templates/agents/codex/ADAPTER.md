# Codex Adapter

## What this provides

| File | Purpose |
|------|---------|
| `WORKFLOW.md` | Symphony-compatible workflow definition |

## What it requires

- Codex CLI access (via OpenAI API or Codex app)
- `AGENTS.md` in the repo root (generated by core harness)

## Entry file

Codex reads `AGENTS.md` natively. No additional entry file needed.

## Hook mechanism

Codex does not currently have a PostToolUse hook equivalent.
Quality gates are enforced via:
- `WORKFLOW.md` — instructs the agent to run `make lint`, `make test`,
  `make check-arch` before completing any task
- `lefthook.yml` — pre-commit and pre-push hooks catch violations at commit time

## WORKFLOW.md

The `WORKFLOW.md` file documents the expected agent workflow in plain language.
It is versioned with the code so teams can evolve it over time.

This file is also the integration point with [Symphony](https://github.com/openai/symphony)
— Symphony reads `WORKFLOW.md` to understand how to orchestrate agents across issues.

## Symphony integration

If you are using Symphony as an orchestration layer:

1. Symphony reads `WORKFLOW.md` to understand the task lifecycle
2. Symphony dispatches Codex per issue in an isolated workspace
3. Codex reads `AGENTS.md` for repo context
4. Codex follows `WORKFLOW.md` steps
5. Human reviews output before merge

The harness provides the environment; Symphony provides the dispatch loop.

## Known limitations

- No post-write hook — boundary violations are caught at commit time (lefthook),
  not at write time. Agents may produce several files before a violation surfaces.
- `WORKFLOW.md` is a convention, not a mechanical enforcement — the agent
  must choose to follow it.
